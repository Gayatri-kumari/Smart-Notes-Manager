React state is memory-resident.

Each tab is a completely separate instance of your application. When you open a new tab, the browser 
"boots up" your React app from scratch. Even if Tab A has a modal open with a 
half-written note, Tab B doesn't know about it because they don't share the same 
RAM. They only "talk" to each other if you write data to localStorage, which you 
only do when you actually save.

So, you don't have to worry about cross-tab "ghost typing"!

Notes on emptyNote in NoteContext.jsx

The return function inside a useEffect is essentially the "Component Will Unmount"
 (or "Pre-Update") cleanup phase. It’s the engine's way of saying: 
 "Before I destroy this component or run this effect again, let me clean up the mess I made."
Exactly! You’ve nailed the concept. It’s the "reset" button that prevents your app from becoming a "memory leak" or having "ghost" behaviors.

To be super precise, React calls that cleanup function in two specific moments:

Before the component unmounts (the user leaves the page or the component is removed).

Before running the effect again (if a dependency in the [] array changes).

1. emptyNote as a plain object variable
   - const emptyNote = { id: idGen(), createdAt: new Date(), ... }
   - This is created once when the component renders or module initializes.
   - idGen() and new Date() execute immediately at declaration time.
   - Reusing this object means the same reference/address is used each time.
   - If you do setNote(emptyNote), the state points to the same object.
   - This can cause stale values and shared reference issues.

2. emptyNote as a factory function
   - const emptyNote = () => ({ id: idGen(), createdAt: new Date(), ... })
   - The function itself is defined once, but its body runs only when called.
   - Every call to emptyNote() returns a fresh object with a new reference.
   - New id and current date are generated each time.
   - This is safer for reset/create note flows.

3. Why use the function in this app
   - Note creation needs a truly fresh blank note state.
   - resetNote() should generate a new object each time.
   - If emptyNote were a shared variable, resetNote would reuse the same object.
   - A factory ensures no accidental shared object reference.

4. React useState initializer behavior
   - useState(emptyNote()) calls emptyNote() only once on mount.
   - After mount, state persists across renders.
   - The render body does not rerun useState initializer on every render.

5. Practical takeaway
   - Use a factory function for objects that need a fresh identity each reset.
   - Treat the note template like a "print a new blank sheet" process, not a single shared sheet.
